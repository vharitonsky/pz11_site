Практична 11 — персональне завдання

Захист клієнта і транспорту: заголовки безпеки, CSP, TLS. Введіть свій user-id зі списку групи, виконайте завдання прямо на сторінці та завантажте відповіді у файл для здачі.

Що і як робити

Інструкція однакова для всіх. Персональні дані з'являться нижче після вводу user-id. Слабкість протоколів/шифрів і проблеми CSP визначаєте самі — на сторінці вердиктів немає.

  1. Заголовки безпеки. За сирими response-заголовками позначте, які захисні заголовки присутні, а які відсутні; які cookie-прапорці бракують (HttpOnly, Secure, SameSite). Перевірити можна через securityheaders.com / Mozilla Observatory.
  2. CSP. Позначте всі проблеми поточної політики та впишіть цільову CSP, що блокує inline-скрипти. Перевіряйте в Google CSP Evaluator.
  3. TLS. Для кожного ввімкненого протоколу/шифру позначте OK чи слабкий (логіка Qualys SSL Labs).
  4. Мапінг атака → захід. Кожній атаці зіставте захід, що її зупиняє.
  5. Здача. Натисніть «Завантажити відповіді (JSON)» і прикріпіть файл до завдання. Самоперевірки тут немає — оцінює викладач.

Приклад (на сторонніх даних — не з вашого варіанту)

Заголовки: у відповіді немає Strict-Transport-Security → відсутній; cookie session=…; Secure без HttpOnly → прапорець HttpOnly відсутній.
CSP: script-src 'self' 'unsafe-inline' → проблема: дозволяє inline-скрипт; немає object-src/frame-ancestors. Цільова: default-src 'self'; script-src 'self'; object-src 'none'; frame-ancestors 'none'.
TLS: TLS 1.0, RC4 → слабкі; TLS 1.3 → OK.
